# Структура документов

Все правила раздела обязательны.

## S01 Назначение и аудитория документа

**Требование.** В начале документа указывайте задачу и аудиторию. При необходимости обозначайте предварительные условия и границы применимости. Для проектных документов указывайте статус сведений.

**Обоснование.** Читатель должен понимать, подходит ли документ для его ситуации.

**Неправильно.** Начинать инструкцию с перечня полей без объяснения назначения.

**Правильно.** Инструкция предназначена для гостей сервиса и описывает заполнение формы, представленной в макете.

**Проверка.** Редактор проверяет наличие назначения, аудитории и существенных условий.

## S02 Последовательность действий

**Требование.** Действия, порядок которых важен, оформляйте нумерованным списком. Каждый шаг должен описывать одно основное действие. Пояснения размещайте рядом с соответствующим шагом.

**Обоснование.** Последовательность помогает выполнить задачу без пропуска действий.

**Неправильно.** Заполните форму, проверьте всё и забронируйте домик.

**Правильно.** 1. Укажите даты проживания. 2. Укажите количество гостей. 3. Заполните контактные данные.

**Проверка.** Автор проходит инструкцию по шагам и проверяет порядок и полноту описания.

## S03 Результаты и ошибки

**Требование.** Указывайте ожидаемый результат процедуры. Для ошибки поясняйте условие возникновения и способ исправления. Различайте предложение, согласованное требование и результат проверки реализации. Не представляйте предполагаемое поведение как проверенное.

**Обоснование.** Читатель должен понимать, завершено ли действие и как устранить проблему.

**Неправильно.** При ошибке появится сообщение.

**Правильно.** Предлагаемое требование: при некорректном адресе рядом с полем **Почта** отображается пояснение. Пользователю предлагается проверить адрес.

**Проверка.** Редактор проверяет результат, способ исправления и источник утверждений о поведении.
