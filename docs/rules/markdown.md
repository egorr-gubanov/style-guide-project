# Markdown и ссылки

## M01 Заголовки

**Обязательно.** Используйте один заголовок H1 на страницу и последовательные
уровни H2 и H3. Не заменяйте заголовки жирной строкой. Короткие заголовки пишите
без точки в конце.

Пример структуры: H1 «Локальный запуск», H2 «Требования», H2 «Порядок запуска».
Проверка: PyMarkdown проверяет число H1 и пропуски уровней; смысл проверяет рецензент.

## M02 Списки и таблицы

**Обязательно.** Для маркированного списка используйте дефис. Отделяйте списки,
заголовки и блоки кода пустыми строками. Таблицы применяйте для сопоставимых данных,
например терминов или параметров. Длинные объяснения пишите абзацами.

Для повторяющихся проверок допустим список с отметками выполнения.
Проверка: PyMarkdown и просмотр собранной страницы.

## M03 Переносимые ссылки

**Обязательно.** Внутри руководства используйте относительные пути к `.md`.
Для источника в другом репозитории укажите полный HTTPS-адрес.
Запрещены рабочие ссылки с `file://`, путями `/Users/`, `/home/` и дисками Windows.

Например, в README исходного приложения ссылка на процесс должна иметь цель
`docs/WORKFLOW.md`, а не путь к домашней папке автора.
Проверка: `scripts/check_docs.py` и строгая сборка MkDocs.
Внешние адреса при необходимости проверяет рецензент; сборка не проверяет их HTTP-статус.

## M04 Понятная подпись ссылки

**Обязательно.** Название ссылки должно объяснять, что откроется.

До: «Инструкция — здесь». После: «Откройте инструкцию локального запуска».
Проверка: `scripts/check_docs.py` отклоняет ссылки с текстом «здесь», «тут»,
«нажмите здесь», `here` и `click here`. Остальные случаи проверяет рецензент.

## M05 Перенос строк в исходнике

**Обязательно.** Ограничивайте обычные строки 120 символами. Для удобства ревью
рекомендуется переносить текст на 80–120 символах.
Линтер отклоняет обычные строки длиннее 120 символов; длинные URL и код разрешены.
Это упрощает просмотр изменений в PR, не меняя отображение абзаца.
Проверка: правило MD013 в `.pymarkdown.json`.
