# Проверка стайлгайда

Проверены два созданных документа: инструкция локального запуска и описание
экрана диагностики. Это редакционная и техническая проверка документации,
а не проверка функций приложения и не пользовательское исследование.

## Редакционная проверка

| Критерий | Локальный запуск | Экран диагностики |
| --- | --- | --- |
| S01 Назначение и аудитория | Указаны разработчик и границы запуска | Указаны участники проекта и статус прототипа |
| S03 Действия и результат | Есть команды и наблюдаемый результат | Есть путь открытия и ограничения кнопок |
| T01 Термины | Название продукта и файлов единообразно | Надписи интерфейса отделены от терминов автора |
| M03 Ссылки | Относительная ссылка на источники | Относительная ссылка на источники |
| I02 Достоверность | Указано, что приложение не запускали | Статические значения обозначены демонстрационными |
| C03 Изображения | Не применимо, изображений нет | Не применимо, изображений нет |

## Что уточнено после применения правил

Первоначальная формулировка «Нажмите Сохранить ответ, чтобы перейти к следующему
заданию» не подтверждается изученным кодом. В окончательном описании она заменена
перечнем видимых элементов и ограничений. Это учебный пример редакторской правки,
а не цитата существующего руководства.

Для ссылок добавлено явное различие между относительным путём в том же репозитории
и HTTPS-ссылкой на другой репозиторий. Нельзя механически переносить ссылку
`docs/WORKFLOW.md` из README приложения в сайт стайлгайда: это другой корень файлов.

Правило доступности дополняется различием между наличием alt-текста и его качеством.
Автоматическая проверка первого признака не подтверждает второй.

## Критерии технической приёмки

Проверки запускаются командой `python scripts/check.py`:

1. PyMarkdown проверяет заголовки, списки, язык блоков кода и базовый alt-текст.
2. Дополнительная проверка отклоняет локальные пути и неинформативные подписи ссылок.
3. MkDocs собирает сайт в строгом режиме и обнаруживает отсутствующие локальные ссылки.
4. Проверка готового HTML проверяет наличие целей внутренних ссылок и якорей.

Результаты фактического запуска находятся в `evidence/local-checks.txt`.
Негативные пробы проверяют, что ошибочные документы действительно отклоняются.

## Оценка качества

Гид достаточен для единообразного оформления двух проверенных документов.
Он связывает требования с наблюдаемыми проблемами проекта и отделяет ручные
проверки от автоматических. Надёжность команд запуска и удобство для учеников
пока не оценивались. Следующий этап — независимое ревью и прохождение инструкций
другим участником, затем уточнение правил по его замечаниям.
