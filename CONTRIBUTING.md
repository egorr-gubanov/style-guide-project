# Внесение изменений

## Предложить изменение

Создайте ветку от актуальной `main`, например `codex/update-booking-guide`.
Измените нужные Markdown-файлы и откройте Pull Request в `main`.
В описании укажите проблему, результат, затронутые правила и выполненные проверки.
Исключения из правил сопровождайте причиной и областью применения.

## Оформление коммитов

Используйте Conventional Commits: `тип: краткое описание`.

- `docs:` — изменение руководства, шаблонов и примеров;
- `ci:` — изменение автоматических проверок и публикации;
- `fix:` — исправление ошибки в инструментах проверки.

Пример: `docs: уточнить описание даты выезда`.

## Локальная сборка

Установите Git и Python 3.12. Склонируйте репозиторий:

```bash
git clone https://github.com/egorr-gubanov/style-guide-project.git
cd style-guide-project
```

Создан каталог проекта; текущий каталог — его корень. Подготовьте окружение:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python scripts/check.py
```

Команды активации приведены для macOS и Linux. В PowerShell используйте
`.venv\Scripts\Activate.ps1` вместо `source .venv/bin/activate`.

Проверка должна завершиться без ошибок. Сайт будет создан в `site/`.
Для предварительного просмотра выполните `python -m mkdocs serve`
и откройте адрес из вывода команды. Остановить сервер можно сочетанием Ctrl+C.

## Ревью

Проверяющий оценивает понятность, терминологию, соответствие макету и статус описываемых возможностей.
При замечании к правилу укажите его идентификатор и предложите исправление.
Автор вносит правки отдельным коммитом. После успешных проверок и одобрения Pull Request
можно включить в `main`; GitHub Actions автоматически опубликует сайт.

При учебном обмене ревью участники обмениваются ссылками на Pull Request.
Каждый оставляет не менее трёх содержательных замечаний, предложений или вопросов к работе партнёра.

## Добавить раздел

1. Создайте Markdown-файл в `docs/` с одним заголовком первого уровня.
2. Для правил укажите идентификатор, обязательность, обоснование, примеры и способ проверки.
3. Добавьте страницу в `nav` файла `mkdocs.yml`.
4. Обновите связанные ссылки, глоссарий и примеры, если изменение их затрагивает.
5. Запустите `python scripts/check.py` и проверьте страницу в браузере.
6. Создайте коммит и Pull Request в `main`.
