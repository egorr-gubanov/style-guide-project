# Оформление Markdown

Все правила раздела обязательны.

## M01 Иерархия заголовков

**Требование.** Используйте на странице один заголовок первого уровня. Подразделы оформляйте последовательно без пропуска уровней. Название должно отражать содержание.

**Обоснование.** Последовательная структура обеспечивает понятную навигацию и оглавление.

**Неправильно.** После заголовка первого уровня сразу использовать третий уровень.

**Правильно.** Первый уровень — название документа, второй — раздел, третий — подраздел.

**Проверка.** Линтер проверяет последовательность уровней. Отдельная проверка считает заголовки первого уровня. Смысл названий оценивает редактор.

## M02 Ссылки и переходы

**Требование.** Между файлами документации используйте относительные пути. Для внешнего источника указывайте полный адрес страницы. Текст ссылки должен пояснять назначение. Не используйте пути к файлам на компьютере автора.

**Обоснование.** Ссылки должны работать после переноса и публикации проекта.

**Неправильно.** Ссылка с текстом «здесь» на файл, доступный только на компьютере автора.

**Правильно.** Ссылка «Инструкция по бронированию» на соответствующую страницу документации.

**Проверка.** Автоматически проверяются локальные пути, общие подписи и наличие целей. Смысл подписи и доступность внешних страниц проверяются вручную.

## M03 Списки и таблицы

**Требование.** Для последовательностей используйте нумерованные списки, для перечислений — маркированные. Таблицы применяйте для сравнения и однотипных сведений. У таблицы должна быть строка заголовков.

**Обоснование.** Форма представления должна соответствовать характеру информации.

**Неправильно.** Поместить всю пошаговую инструкцию в одну ячейку таблицы.

**Правильно.** Оформить действия списком, а сведения о полях — таблицей с колонками «Поле», «Назначение», «Ограничения».

**Проверка.** Синтаксис Markdown проверяется автоматически, обоснованность формы представления — редактором.
