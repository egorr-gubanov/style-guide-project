# Выбор проекта для стайлгайда

Изучены доступные README и процессные документы четырёх реальных проектов.
Это анализ документации, а не аудит качества приложений.

## Сравнение кандидатов

| Проект | Что изучено | Наблюдение для лабораторной |
| --- | --- | --- |
| ЕГЭРывок | README, WORKFLOW, CONTRIBUTING, компоненты | Локальные ссылки и статические данные |
| Здание | README, LOCAL_SETUP, ROLE_ACCESS | Разные инструкции запуска и матрица прав |
| Web Game Studio | README, STUDIO, STATE | Повтор заголовка в README, статусы в STATE |
| Belot Web App | README | В одном документе объединены запуск, серверная настройка, разработка и функции игры |

## Почему выбран ЕГЭРывок

В репозитории `egorr-gubanov/ege_jerk` уже есть маршрут `/diagnostic`, экран
результатов и описанный процесс PR. Можно разработать стайлгайд на реальном
материале и проверить его на двух документах без изменения исходного приложения.

В README ссылки на документацию используют абсолютные пути компьютера автора.
Для совместной работы нужны относительные ссылки внутри одного репозитория или
полные HTTPS-ссылки на внешний источник.

В компоненте диагностики значения прогресса и времени заданы в разметке.
Обработчики сохранения ответа в изученном компоненте отсутствуют. Поэтому
документация должна различать видимый прототип и подтверждённую функцию.

## Ограничения исследования

Изучены документы и отдельные исходные файлы. Приложения не запускались.
Доступность всех функций, работа серверов и состояние развёртывания не проверялись.
Вывод о статичности относится к изученным компонентам на дату исследования.
Ссылки и контрольные идентификаторы файлов приведены в [источниках](sources.md).
