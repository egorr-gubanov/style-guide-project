# Предлагаемые требования к проверке формы

## Назначение и аудитория

Документ предназначен для разработчиков и проверяющих будущую реализацию формы сервиса «Сосны».
Он определяет предлагаемые проверки данных и способ описания ошибок.

## Источник и статус

Источник полей — [макет «Сосны»](https://www.figma.com/design/Hrn06cbi1J6furVPfOIbso/ЛР1).
Требования ниже являются предложениями и требуют согласования.
Макет не подтверждает реализацию этих проверок.

## Требования

| Код | Предлагаемое требование | Пример проверки |
| --- | --- | --- |
| FV01 | Проверять заполнение дат, количества гостей и контактов. Состав обязательных полей согласовать | Пустое обязательное поле: показать, что его нужно заполнить |
| FV02 | Проверять корректность дат; дата выезда должна быть позже даты заезда | Одинаковые даты: предложить изменить дату выезда |
| FV03 | Принимать положительное целое количество гостей; максимум определяется согласованной вместимостью | Значение 0: пояснить допустимое количество |
| FV04 | Проверять синтаксис электронной почты по согласованному алгоритму; существование ящика этим не подтверждается | guest.example.com без символа @: предложить проверить адрес |
| FV05 | Указывать ошибочное поле и способ исправления без обвинения пользователя | Вместо «Неверные данные»: «Укажите дату выезда позже даты заезда» |
| FV06 | При показе ошибки сохранять остальные значения в форме; сохранение после закрытия страницы не предполагается | Ошибка в одном поле: остальные значения остаются в форме |

Примеры содержат демонстрационные значения и не относятся к реальному бронированию.

## Открытые вопросы

Необходимо согласовать вместимость домика, допустимый диапазон дат, формат телефона,
обработку пробелов, ограничения длины текста и поведение при недоступности сервера.
Отдельно требуется определить момент подтверждения бронирования, необходимость оплаты и способ уведомления.
Эти решения относятся к требованиям продукта и не устанавливаются стайлгайдом.

## Условия проверки реализации

После согласования для каждого требования проверьте подходящие и неподходящие значения
и поведение после исправления ошибки. Проверка полей не подтверждает доступность домика
и создание бронирования.

Проверки в браузере и на сервере описываются после определения архитектуры приложения.
Документ не подтверждает наличие серверной части.
