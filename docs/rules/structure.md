# Структура документов

## S01 Назначение в начале

**Обязательно.** Начинайте документ с названия, цели, аудитории и границ.
Для инструкции укажите необходимые права и инструменты до первого действия.

Пример: «Инструкция описывает локальный запуск интерфейса. Нужен доступ
к закрытому репозиторию. Она не подтверждает работу регистрации и оплаты».
Проверка: сравнение с [шаблонами](../templates.md).

## S02 Одна инструкция для одной цели

**Обязательно.** Разделяйте запуск разработчика, пользовательскую справку и
администрирование. Не включайте настройку производственного сервера в быстрый старт.

Пример: «Локальный запуск» и «Развёртывание» — разные документы.
Проверка: рецензент проверяет цель каждого раздела.

## S03 Шаги и ожидаемый результат

**Обязательно.** Используйте нумерованный список для последовательных действий.
После команды или группы действий опишите наблюдаемый результат и способ проверки.
Разветвление помещайте перед шагом, к которому оно относится.

Пример: «Выполните `npm run dev`. В терминале появится адрес сервера».
Проверка: ручное прохождение инструкции; если оно не выполнено, это явно укажите.

## S04 Статус и актуальность

**Обязательно.** Для инструкций и описаний функций указывайте источник проверки,
дату и ограничения. При изменении интерфейса обновляйте документацию в том же PR.

Пример: «Проверено по `src/components/diagnostic-page.tsx` 22 октября 2026 года.
Функциональный запуск не проводился».
Проверка: рецензент сверяет заявление с доступным доказательством.
